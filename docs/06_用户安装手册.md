# 用户安装手册

本文说明如何在本机安装并运行 UniversalContract 参考实现，包括通用的多
Agent 编排、离线测试，以及 AgentScope 与 MAF Magentic 的完整示例。

## 1. 环境要求

- Python `>=3.11`；已在 Python 3.12 环境验证。
- `pip` 与可选的虚拟环境工具 `venv` 或 Conda。
- 离线测试不需要模型 API Key；需要真实 MCP 与 LLM 的 demo 需要相应凭据。
- 生产模型、远程 MCP 服务或 HTTP A2A transport 按其各自的认证方式另行配置。

## 2. 获取代码并创建隔离环境

进入本项目目录后创建虚拟环境：

```bash
cd universal-contract-v2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

使用 Conda 时，可替换为：

```bash
conda create -n universal-contract python=3.12
conda activate universal-contract
cd universal-contract-v2
python -m pip install --upgrade pip
```

## 3. 用 pip 安装依赖

`requirements.txt` 包含运行当前完整参考实现所需的直接依赖：MAF 的 workflow /
Magentic 引擎、AgentScope runtime，以及本项目直接导入的类型扩展。

```bash
python -m pip install -r requirements.txt
```

当前验证基线为：

| 组件 | 要求 | 已验证版本 |
|---|---|---|
| Python | `>=3.11` | 3.12 |
| `agent-framework` | `>=1.17,<2.0` | 1.17.0 |
| `agentscope` | `>=2.0,<3.0` | 2.0.6 |

`agentscope` 会安装其自身的运行依赖，例如 `pydantic`。如果只阅读纯契约、A2A
协议或 Harness 代码而不运行 MAF / AgentScope 示例，可以按实际使用的 adapter 缩减
安装项；`requirements.txt` 则确保全部随仓库提供的验证和示例可直接运行。

## 4. 验证安装

在项目根目录执行：

```bash
python tests/test_offline.py
```

预期结尾为：

```text
ALL 48 CHECKS PASSED
```

该测试不访问外部模型服务，覆盖 Harness 标准上下文、A2A 传输、各种编排 mode
的协作状态共享、内置 REACT 循环、Magentic adapter 以及 AgentScope adapter。

## 5. 运行示例

### AMap 与 Maqami 出行示例

在仓库根目录 `.env` 或当前 shell 配置 LLM 与 AMap MCP：

```bash
export UNIVERSAL_CONTRACT_LLM_BASE_URL="https://your-llm-gateway/v1"
export UNIVERSAL_CONTRACT_LLM_API_KEY="..."
export AMAP_MCP_ENDPOINT="https://your-amap-mcp-endpoint"
python demo/react-orchestration-2-agent/demo.py
```

该 demo 使用确定性 Magentic manager，严格按“AMap 天气/POI -> Maqami 航班报价”
顺序执行两个 Worker。Maqami 使用匿名 MCP，白名单仅允许只读的
`post_flights_rates` 工具；不会暴露预订、取消或支付能力。

### YAML 配置与 FastAPI HTTP A2A 出行示例

配置驱动版本在 `demo/react-orchestration-2-agent-fastapi/`。它通过 `usecase.yaml`
选择已注册 agent 模板，并通过进程内 FastAPI 路由和 `HttpA2ATransport` 调用 Worker：

```bash
python demo/react-orchestration-2-agent-fastapi/demo.py
```

默认使用 `httpx.ASGITransport`，因此不启动端口监听；调用仍是标准 HTTP POST/JSON A2A
协议。将 FastAPI app 部署为 Uvicorn 服务并替换 worker endpoint 后，可以改为跨进程 HTTP 调用。

生产环境的独立 Worker 服务、同步/异步执行、企业 IAM、mTLS、API Gateway 与 tenant
隔离请参见 [部署与认证指南](07_部署与认证指南.md)。数字员工平台的账户注册、JWT 登录和
租户切换见 [用户认证与隔离](08_用户认证与隔离.md)。

### 数字员工平台：以 token profile 体验多租户

平台默认 `AUTH_PROFILE=local`，用于显式无认证开发。要体验用户、租户与动态资源隔离，
从仓库根目录安装平台额外依赖后启动：

```bash
python -m pip install -r demo/digital-workforce-platform/backend/requirements.txt
cd demo/digital-workforce-platform
export AUTH_PROFILE=token
export JWT_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
PYTHONPATH=backend:../.. python -m uvicorn digital_workforce.main:app --reload --port 8000
```

另开终端启动 `frontend/` 下的 `npm run dev`，在“身份与租户”页面注册第一个用户和租户。
临时生成密钥适合本地演示；重启时更换密钥会使当前登录 token 失效。生产环境应由 Secret
Manager、Vault、KMS 或部署平台注入稳定的 `JWT_SECRET`。

## 6. 接入生产 runtime

`AgentScopeRuntimeAdapter` 的构造参数是已配置的 AgentScope `ChatModelBase`。将
示例中的离线模型替换为生产模型，并通过环境变量或密钥管理系统提供凭据；不要将
密钥写入 `HarnessSpec`、`SharedSession` 或 A2A payload。

新 runtime 只需实现 `HarnessRuntimeAdapter`。其 `RunningAgent` 必须完整注入
`HarnessExecutionContext.context_items`，因为 `ProviderHarness` 已自动提供：

- `contract.collaboration`：当前多 Agent 协作快照；
- `contract.session.facts`：可跨 runtime 迁移的长期业务事实；
- `contract.session.messages`：中立的会话记录。

单 Agent 的 ReAct/tool loop 由具体 runtime adapter 与该框架的原生 agent 实现；多
Agent 的分派、共享状态和 REACT 协作循环则由 `create_workflow()` 与 Harness Contract
负责。具体适配义务与验收项见 [框架适配指南](04_框架适配指南.md)，共享状态规则见
[协作状态共享](05_协作状态共享.md)。

## 7. 常见问题

| 现象 | 处理方式 |
|---|---|
| `ModuleNotFoundError: agent_framework` | 在激活的环境中重新执行 `python -m pip install -r requirements.txt`。 |
| `ModuleNotFoundError: agentscope` | 同上；确认执行命令的 `python` 与安装依赖的 `python -m pip` 属于同一环境。 |
| 示例显示 function invoking 警告 | 当前模型客户端不支持工具调用的提示；请使用支持 function calling 的模型以获得完整 agent 能力。 |
| AMap 或 Maqami MCP 连接失败 | 检查端点、网络代理和 TLS 信任链；可设置 `UNIVERSAL_CONTRACT_TIMING=1` 输出各阶段耗时。 |
