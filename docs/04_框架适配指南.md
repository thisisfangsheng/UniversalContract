# 框架适配指南

> 本文档回答：要把 MAF / AgentScope / LangGraph / OpenAI Agents SDK /
> Google ADK / DeepAgents 的智能体接入本项目，适配器需要写什么？
> 各框架的招牌特性会不会被封装丢掉？
>
> 结论先行：每接入一个框架 = 实现 **4 个成员**的适配器（HarnessRuntimeAdapter）；
> 六框架的原生能力都有对应通道，个别框架没有的能力走降级路径（已列明）。

---

## 1. 适配器要实现的四个成员

```python
class MyFrameworkRuntime:                        # 满足 HarnessRuntimeAdapter 接口
    runtime_name = "my-framework"                # 框架标识（也是会话运行记录的键）

    def capabilities(self) -> frozenset[Capability]:
        return frozenset({Capability.DURABLE_SESSION, Capability.TOOL_LOOP})

    async def build(self, spec: HarnessSpec, providers: HarnessProviders) -> RunningAgent:
        # ★ 翻译发生在这里：把中立声明变成框架原生构造
        #   spec.instructions → 系统提示
        #   spec.tools        → 框架的 MCP 工具封装
        #   spec.skills       → 框架的技能加载器（或降级注入）
        #   providers         → 会话存取（框架私有状态自己管，ID 记入运行记录）
        ...

    async def close(self) -> None:
        # 释放框架资源：模型客户端连接、MCP 连接、编译产物等
        ...
```

产出的 `RunningAgent` 只需要两个方法：`run(context)` 返回终态，
`run_stream(context)` 流式返回。**它收到的输入只有 `HarnessExecutionContext`
（请求 + 会话 + 上下文条目 + Provider 包），没有任何框架外类型。**

### 标准上下文注入是适配器的强制义务

`ProviderHarness` 会在每次调用前无条件生成并排序以下 `ContextItem`；调用方不需要为
多 Agent 协作或跨 runtime 记忆单独编写 ContextProvider：

| 保留标签 | 内容 |
|---|---|
| `contract.collaboration` | 当前 Worker 的工作流事实、任务输入、前序回执与依赖回执 |
| `contract.session.facts` | `SessionProvider` 恢复的长期结构化事实 |
| `contract.session.messages` | 本次调用开始前的中立会话记录 |

每个 `RunningAgent` 实现**必须完整注入** `context.context_items`：对话型框架可追加为
prompt/message，状态图框架可写入其 native state。adapter 不应自行读取
`request.metadata["collaboration"]` 或格式化 `SharedSession`，因为这样会使新 runtime
遗漏协作状态。框架私有的 memory、checkpoint 和连接对象仍不得写入 `SharedSession`。

## 2. MCP 服务器声明 → 六框架原生写法对照

契约里的 `McpServerSpec` 字段是六家原生参数的最大公约数：

| McpServerSpec 字段 | MAF | AgentScope | LangChain/LangGraph | OpenAI SDK | Google ADK |
|---|---|---|---|---|---|
| `name` | `name=` | `name=` / dict key | dict key | `name=`（可选） | ⚠️ 无原生 → 包装层记录 |
| `transport` + `url` | 类选择 + `url=` | config 选择 + `url=` | `{"transport": "http", "url": ...}` | 类选择 + `params.url` | ConnectionParams 选择 + `url=` |
| `transport` + `command/args/env` | `MCPStdioTool(...)` | `StdioMCPConfig(...)` | `{"transport": "stdio", ...}` | `MCPServerStdio(params)` | `StdioConnectionParams(...)` |
| `headers` | `header_provider` | ⚠️ 文档未列 | `headers=` | `params.headers` | `headers=` |
| `allowed_tools` | `allowed_tools=` | `enable_tools=` | 调用后过滤 | `tool_filter=` | `tool_filter=` |
| `blocked_tools` | — | `disable_tools=` | 调用后过滤 | — | — |
| `requires_approval` | `approval_mode=` | 权限系统 | ❌ 忽略+记录 | ❌ 忽略+记录 | ❌ 忽略+记录 |
| `request_timeout_s` | `request_timeout=` | ⚠️ | ⚠️ | ⚠️ | ⚠️ |

**空白格的处理原则**：该框架没有的能力，适配器忽略该字段并记录日志，
不报错、不阻塞——契约不按最弱者削足适履。

六家完整构造语句示例（真实可抄）：

```python
# MAF
MCPStreamableHTTPTool(name=spec.name, url=spec.url,
                      allowed_tools=list(spec.allowed_tools) or None,
                      approval_mode="always_require" if spec.requires_approval else None,
                      request_timeout=spec.request_timeout_s)

# AgentScope（stateful 客户端需要显式 connect/close，映射到 build/close）
MCPClient(name=spec.name, is_stateful=True,
          mcp_config=HttpMCPConfig(url=spec.url),
          enable_tools=list(spec.allowed_tools) or None)

# LangChain / LangGraph / DeepAgents
MultiServerMCPClient({spec.name: {"transport": "http" if spec.url else "stdio",
                                  "url": spec.url, "headers": dict(spec.headers),
                                  "command": spec.command, "args": list(spec.args)}})
tools = await client.get_tools()

# OpenAI Agents SDK
MCPServerStreamableHttp(params=StreamableHttpParams(url=spec.url, headers=dict(spec.headers)),
                        tool_filter=list(spec.allowed_tools) or None)

# Google ADK
McpToolset(connection_params=StreamableHTTPConnectionParams(url=spec.url, headers=dict(spec.headers)),
           tool_filter=list(spec.allowed_tools) or None)
```

## 3. 技能（SkillSpec）→ 六框架对照

| SkillSpec | MAF | AgentScope | DeepAgents | OpenAI / ADK / LangGraph |
|---|---|---|---|---|
| `source="path"` | `SkillsProvider.from_paths([path])` | `Toolkit(skills_or_loaders=[path])` | `create_deep_agent(skills=[path])` | 降级：ContextItem 注入 |
| `source="inline"` | `SkillsProvider(InlineSkill(...))` | `Skill` 对象进 Toolkit | `StateBackend` + `invoke(files=...)` | 降级：ContextItem 注入 |
| `source="mcp"` | `SkillsProvider(MCPSkillsSource(server))` | ❌ 降级 | ❌ 降级 | ❌ 降级 |
| `allowed_tools` | frontmatter 原生 | frontmatter 原生 | frontmatter（allowed-tools） | 不适用 |
| `enable_scripts` | 控制 `run_skill_script` 工具暴露 | 需 agent 自备 shell 工具 | 需沙箱 backend | 不适用 |

**降级路径说明**：没有原生技能机制的框架，适配器把技能"名称+描述"作为
常驻上下文（一级披露）、"全文"按需注入（二级披露）——用普通 ContextItem
实现，效果是技能在所有框架上都可用，只是无原生机制时 token 成本略高。

## 4. Agent 构造 → 四框架对照（含特性保留）

同一份 HarnessSpec（含工具与技能声明）在四家适配器 build() 中的翻译：

```python
# MAF
Agent(name=..., instructions=spec.instructions,
      tools=[MCPStreamableHTTPTool(...)],                       # MCP 工具
      context_providers=[SkillsProvider(...)])                  # 技能走上下文提供者

# AgentScope
ReActAgent(name=..., sys_prompt=spec.instructions, model=...,
           toolkit=Toolkit(mcps=[MCPClient(...)],               # MCP + 技能都进工具箱
                           skills_or_loaders=[...]),
           memory=InMemoryMemory())                             # native 记忆自己管

# LangGraph
graph = create_react_agent(model, tools=await client.get_tools(),
                           checkpointer=MemorySaver())          # native 检查点自己管
result = await graph.ainvoke(state, config={"configurable": {"thread_id": session_id}})

# OpenAI Agents SDK
agent = Agent(name=..., instructions=spec.instructions,
              mcp_servers=[MCPServerStreamableHttp(params=...)],
              output_type=RefundDecision)                       # 结构化输出的原生形态
result = await Runner.run(agent, input_text)
```

### 特性保留矩阵（审计核心）

| 各框架招牌特性 | 契约通道 | 结论 |
|---|---|---|
| 四家全部：流式输出 | `RunningAgent.run_stream` | ✅ |
| OpenAI `output_type` / MAF 结构化响应 / AS `structured_model` / LangGraph state | `AgentResult.data` | ✅ |
| LangGraph `interrupt` / OpenAI 工具审批 / MAF `request_info` | `status=needs_approval/needs_input` + `resume` 载荷 | ✅ |
| LangGraph checkpointer / OpenAI Sessions / AS memory / MAF session | adapter 内自管，ID 记入 `runtime_references` | ✅ |
| OpenAI handoffs / guardrails | adapter 内部机制（与编排层的"接力"模式不同层，不冲突） | ✅ |
| LangGraph 自定义 state schema / 子图 | adapter 私有，不进契约 | ✅ |

## 5. 编排层（控制面）的边界

| 问题 | 答案 |
|---|---|
| 换框架后，我的 Worker 能被编排吗？ | 能。编排器只依赖 `WorkerEndpoint` 接口，Worker 用什么框架、在本地还是远程均无感知 |
| 反思循环能用哪些引擎？ | `engine="magentic"`（MAF 自带循环，生产默认）或 `engine="builtin"`（确定性规则，无 LLM） |
| 能用 LangGraph 做编排引擎吗？ | 技术可行（StateGraph 可实现同语义的循环图），当前仓库未提供实现；统一入口 `create_react_workflow(engine=...)` 已为新增引擎预留位置 |
| OpenAI handoffs 能当编排引擎吗？ | 不建议：handoffs 是 agent 内部的转交，没有工作流检查点与全链审计，与本项目的编排语义不同层 |

## 6. 测试清单（接新框架时的验收点）

- [ ] `validate()` 通过：申请能力 ⊆ 声明能力；tools/skills 引用一致
- [ ] `run()` 后共享会话里有对话记录与运行 ID，且不含框架私有对象
- [ ] 同一 session_id 换另一个框架的适配器，能读到前者的会话内容
- [ ] 不配置业务 `ContextProvider` 时，native runtime 仍收到三个 `contract.*` 标准 ContextItem
- [ ] native runtime 实际使用完整 `context.context_items`，未绕过 Harness 自行读取协作 metadata
- [ ] `McpServerSpec` 翻译后工具可被 agent 调用，白名单生效
- [ ] `SkillSpec` 在有原生机制的框架走原生，无机制的走 ContextItem 注入
- [ ] 结构化结果（data）能穿过 A2A 协议层出现在 `WorkerResult.output`
- [ ] `resume` 载荷能从 `WorkerTask` 一路到达框架的中断恢复机制
